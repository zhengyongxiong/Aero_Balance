# AeroBalance 双电磁阀控制设计

## 目标

在现有 XIAO ESP32S3、BMP390 和 Web Bluetooth 数据链路上增加两个独立泄压电磁阀。固件持续采集环境气压并以 1 Hz 上报，App 可向左阀或右阀发送短脉冲命令，所有异常路径均强制关阀。

## 硬件约束

- 左泄压阀驱动输入：XIAO `D1`，对应 ESP32-S3 `GPIO2`。
- 右泄压阀驱动输入：XIAO `D2`，对应 ESP32-S3 `GPIO3`。
- 两个驱动输入均为高电平开启、低电平关闭。
- BMP390 继续使用 `D4/SDA/GPIO5` 和 `D5/SCL/GPIO6`，与阀门引脚无冲突。
- 电磁阀必须通过 MOSFET 或驱动板供电，并使用续流二极管；不得由 GPIO 直接驱动线圈。
- 固件默认禁止两个阀同时开启，避免未知电源能力下的电流过载。

## 控制模型

首版只提供安全脉冲控制，不提供持续锁定开启，也不根据 BMP390 自动闭环控制。BMP390 测量的是环境压力，不是耳道压力，不能作为安全闭环反馈。

- 可选目标：左阀或右阀。
- 允许脉冲范围：50 至 500 ms。
- 超出范围的命令被拒绝，不自动截断。
- 阀门正在开启时拒绝新的脉冲命令。
- `STOP_ALL` 命令可随时立即关闭两个阀。
- 上电、BLE 断开、传感器连续读取失败、命令超时和固件重启均保持或恢复低电平关阀。

## BLE 协议

现有服务 UUID `FFE0` 和遥测特征 `FFE1` 保持不变。新增控制特征：

`0000ffe2-0000-1000-8000-00805f9b34fb`

控制特征支持 Write、Read 和 Notify。App 使用可靠写入发送固定 6 字节命令：

| 字节 | 含义 |
| --- | --- |
| 0 | 协议版本，固定为 `1` |
| 1 | 操作码：`1=PULSE`、`2=STOP_ALL` |
| 2 | 阀门：`0=LEFT`、`1=RIGHT`、`255=ALL` |
| 3-4 | 持续时间，little-endian 毫秒；STOP_ALL 时为 0 |
| 5 | App 命令序号，0-255 循环 |

固件通过同一特征发送 6 字节确认：

| 字节 | 含义 |
| --- | --- |
| 0 | 协议版本 `1` |
| 1 | 对应的命令序号 |
| 2 | 结果：`0=OK`、`1=INVALID`、`2=BUSY`、`3=SENSOR_FAULT` |
| 3 | 左阀状态，0 或 1 |
| 4 | 右阀状态，0 或 1 |
| 5 | 当前故障码 |

BLE 链路已包含校验和可靠写入语义，控制包不增加应用层 CRC。

## 遥测协议

遥测仍使用 JSON 和 1 Hz 通知。BMP390 保持 5 Hz 采样并对最多 5 个样本求平均。为控制通知长度，移除固定的 `phase:"sensor"` 字段，以 `source:"bmp390"` 识别真实传感器包，并新增：

- `v:[left,right]`：左右阀实时状态。
- `f`：固件故障码。

App 解析器同时兼容旧版含 `phase:"sensor"` 的包和新版阀门状态包。

## App 交互

设备页连接成功后显示：

- 左阀脉冲按钮。
- 右阀脉冲按钮。
- 全部关闭按钮。
- 左右阀实时状态、最近命令结果和固件故障状态。

脉冲按钮固定发送 250 ms，后续可在明确硬件响应后增加 100/250/500 ms 选择。App 在未连接、正在重连或命令等待确认时禁用脉冲按钮。

## 故障处理

- 固件阀门截止由 `millis()` 截止时间控制，不使用 `delay()`。
- BLE 断开回调立即关闭两个阀，然后重新广播。
- BMP390 三次连续读取失败立即关闭两个阀并进入现有 5 秒重试流程。
- 无效长度、版本、操作码、阀门或持续时间不会改变 GPIO。
- App 写入失败或确认超时后显示失败，但不假设阀门状态；状态以遥测为准。

## 验证

- Arduino CLI 编译目标：`esp32:esp32:XIAO_ESP32S3`。
- 静态验证上电和全部异常路径都调用关阀逻辑。
- 协议测试覆盖合法脉冲、全部关闭、非法包、忙状态和传感器故障。
- 浏览器测试覆盖控制按钮使能状态、写入字节和确认结果展示。
- 实机验证串口输出、BLE 遥测和 GPIO 状态；先不接线圈，用万用表或 LED 验证 D1/D2 高低电平，再接驱动板和阀门。
